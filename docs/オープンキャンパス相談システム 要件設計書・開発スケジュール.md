# オープンキャンパス相談システム 要件設計書・開発スケジュール

Nov 12, 2026 · @Konosuke

## 1. 概要

オープンキャンパスの個別相談で、来場者がスマホから整理券を受け取り、待ち状況と呼出をリアルタイムに確認できるシステムを Firebase（GCP 東京リージョン）で構築します。本番は 2027年3月20日（土）の開催を想定し、開発期間は約18週間です。

**目的**

- 相談ブース前の行列をなくし、来場者が待ち時間を他の企画に使えるようにする
- 学生・教員の相談ブースの稼働率を上げる（1組10分、ブース14で1時間あたり約84組を処理）
- 個人を特定する情報を取得せず、問診メモも当日中に削除する

**対象範囲**

| 区分 | 含む | 含まない |
| --- | --- | --- |
| 来場者 | 入場コード照合、相談種別の選択・相談員一覧（学生相談のみ）、発券、整理券モニター、呼出通知 | アプリのインストール、プッシュ通知（画面を開いている間のみ通知） |
| スタッフ | ログイン、担当枠の占有、呼出・相談開始・完了・スキップ・復帰、受付停止、上限変更 | 実名での登録 |
| 管理者 | イベント設定、コード発行、枠の CSV 取込、強制解除、統計閲覧 | 予約の事前受付 |

**元資料**: 「オープンキャンパス個別相談 整理券配布兼来場者モニターシステム 要件定義書」Ver1.0（2026年11月11日）と、それをもとにした詳細設計・実装仕様の検討結果。

## 2. 利用者とユースケース

利用者は4種類で、それぞれ認証方法と見られる範囲が異なります。想定規模は1回あたり来場約150組、学生・教員ブース各 7〜8 です。

| 利用者 | 人数（目安） | 認証 | 主なユースケース |
| --- | --- | --- | --- |
| 来場者（高校生・保護者） | 約150組/日 | 匿名ログイン＋7桁の入場コード（会場掲示の QR または手入力） | 相談種別を選ぶ（学生相談は相談員も選ぶ）、問診を入力して発券、待ち状況を見る、呼出を受ける、キャンセルする |
| 学生スタッフ | 7〜8名 | 8桁のスタッフコード＋枠の占有 | 担当枠を取る、次を呼ぶ、相談開始・完了、不在スキップと復帰、受付停止 |
| 教員スタッフ | 7〜8名 | 8桁のスタッフコード＋ブース番号 | 全学1本の教員キューから呼ぶ、相談開始・完了、キュー上限の変更 |
| 管理者（事務局） | 2名 | ID・パスワード＋認証アプリのワンタイムコード（TOTP） | イベントとコードの設定、枠の登録、当日の監視と異常対応、統計の確認 |

**来場者の基本の流れ**

1. 会場のポスターの QR を読む（または7桁を入力）
2. 学生相談か教員相談かを選ぶ
   - 学生相談：相談員一覧から相談員を選ぶ（タグは OR で絞り込み）
   - 教員相談：相談員は選ばず、そのまま 3 へ進む（全学1本の教員キューに並ぶ）
3. 学年・相談テーマ・自由記述（200字まで）を入力して整理券を受け取る
4. 整理券画面で「あと○組・およそ○分」を確認しながら待つ
5. 呼出を受けてブースへ行き、相談する
6. 不在でスキップされた場合は、10分以内にブースへ行けば列の先頭に戻れる

## 3. 機能要件

書き込みはすべて Cloud Functions のトランザクションで行い、待ち上限・二重発券・重複呼出をサーバ側で防ぎます。優先度は Must（本番に必須）と Should（間に合わなければ運用で代替）です。

### 3.1 来場者

| ID | 機能 | 要件 | 優先 |
| --- | --- | --- | --- |
| V-01 | 入場コード照合 | 7桁（先頭0可）。QR の `#code=` は読込直後に URL から消す。端末ごと 5回/10分、IP ごと 50回/10分で試行制限 | Must |
| V-02 | 相談種別の選択・相談員一覧 | まず学生相談／教員相談を選ぶ（それぞれ待ち組数・目安時間・状態を表示）。学生相談は相談員一覧へ進み、タグ絞り込み（OR）、待ち組数・目安時間・状態（すぐ案内可／受付中／一時停止中／準備中）をリアルタイム表示。教員相談は相談員の選択をせず発券（V-03）へ直接進む | Must |
| V-03 | 発券 | 学年・相談テーマ（5個まで）・自由記述（200字）。有効な整理券は1端末1枚。停止中・満員なら理由を表示 | Must |
| V-04 | 整理券モニター | 番号、予約先、あと○組、およそ○分（5分単位）、状態別の表示 | Must |
| V-05 | 呼出通知 | 全画面バナー、タブ名変更、振動（Android）、音（許可時）。画面を開いている間のみと明記 | Must |
| V-06 | キャンセル | 待ち・呼出中・スキップ中のみ。確認ダイアログあり | Must |
| V-07 | スキップ復帰の案内 | 残り時間を表示し、10分以内なら列の先頭に戻れることを案内 | Must |
| V-08 | 画面を消さない | Wake Lock のトグル | Should |

### 3.2 スタッフ

| ID | 機能 | 要件 | 優先 |
| --- | --- | --- | --- |
| S-01 | ログイン | 8桁コード＋役割選択。端末ごと 3回/10分 | Must |
| S-02 | 担当設定 | 学生は未占有の枠を1つ占有（1枠1台）。教員はブース番号を設定 | Must |
| S-03 | 待機リスト | 番号・学年・テーマ・待ち時間。タップで問診メモ | Must |
| S-04 | 呼出・開始・完了 | 状態に応じた主ボタン1つ。呼出3分超で口頭呼出を促す、相談15分超で注意色。完了時に問診メモを即削除 | Must |
| S-05 | 不在スキップと復帰 | スキップ後10分以内は［復帰］で列の先頭へ（上限超過可） | Must |
| S-06 | 5秒の取り消し | 完了・スキップは5秒待ってから送信 | Should |
| S-07 | 受付停止 | 学生枠・教員相談とも、担当スタッフが自分の列の新しい受付を止める／再開する。停止中も並んでいる方は呼べる。止めた理由（担当の停止・上限到達・全体停止）を画面に出す | Must |
| S-08 | 列の上限の変更 | ［−］［＋］で即時反映。学生枠は1〜10（1刻み、既定5）を占有中の学生スタッフが、教員相談は10〜80（5刻み、既定40）を教員スタッフが変更。変更履歴を記録 | Must |
| S-09 | 担当を外れる | 対応中がないときのみ。列は残る | Must |

### 3.3 管理者

| ID | 機能 | 要件 | 優先 |
| --- | --- | --- | --- |
| A-01 | ログイン | ID＋パスワード（12文字以上）＋TOTP 必須。初回はパスワード変更と TOTP 登録。30分無操作でログアウト | Must |
| A-02 | イベント設定 | 開催日時、相談時間（既定10分）、スキップ復帰時間（既定10分）、相談テーマ | Must |
| A-03 | コード発行 | 入場用・スタッフ用を乱数で生成。推測されやすいコードを拒否。ポスター用 QR URL | Must |
| A-04 | 枠の登録 | CSV 一括取込と個別編集。URL・SNS ID を含む入力を拒否 | Must |
| A-05 | 当日の操作 | 開場・閉場、占有の強制解除、列ごとの受付停止と上限変更、会場全体の受付の一時停止（確認を挟む。列ごとの停止設定は再開後も残る） | Must |
| A-06 | ダッシュボード | 全体の待ち状況、警告（スタッフコードの失敗急増、発券数の急増） | Should |
| A-07 | 統計 | 学年×テーマの件数、平均待ち・相談時間、時間帯別の発券数 | Should |

### 3.4 自動処理（1分ごと）

- 開場時刻で受付開始、閉場時刻で残りの整理券を無効化し問診メモを全削除
- スキップから10分を過ぎた整理券を無効化
- 閉場から1時間後に統計を集計し、整理券・枠・画像・匿名ユーザーを削除

## 4. 非機能要件

費用は開催月で数十〜数百円、個人情報は取得せず当日削除、という二点が設計の前提です。

| 区分 | 要件 |
| --- | --- |
| 性能 | 発券・呼出の応答 p95 300ms 以内。開催日は `issueTicket`・`callNext` を常駐1台（minInstances 1） |
| 同時利用 | 整理券保持者の最大は約75人（学生 7枠×5組＋教員 40組）。一覧閲覧者を含めて数百端末 |
| 可用性 | 障害時は紙の番号札＋口頭呼出に切替。判断は管理者 |
| 費用 | Blaze（従量課金）。上限は開催月で $25。予算アラート ¥1,000/月（50・90・100% で通知）、自動停止なし |
| セキュリティ | クライアントからの書込は全拒否。App Check を全サービスで強制。管理機能は TOTP 済みトークンのみ。画像は `getBlob()` で取得し公開 URL を使わない |
| プライバシー | 氏名・学校名・連絡先は取得しない。問診メモは完了・キャンセル時に即削除、閉場時に全削除。閉場＋1時間で統計以外を物理削除。バックアップ（PITR）は有効にしない。SDK はメモリキャッシュのみ |
| データ所在 | すべて asia-northeast1（東京）。このシステム専用の GCP プロジェクト |
| 対象端末 | iOS Safari 16.4 以上、Android Chrome 最新2版。インストール不要 |
| 使いやすさ | 文字16px 以上。状態は色だけでなく文言でも示す。コードは `038-4712`（来場者）、`0384-7125`（スタッフ）と区切って表示 |
| 監査 | 上限変更、コードの表示・再発行、管理者ログインを `auditLog` に記録（当日削除） |

## 5. システム構成・データ設計・画面一覧

静的 SPA（React＋Vite＋TypeScript）を Firebase Hosting で配信し、書き込みは Cloud Functions、配信は Firestore の `onSnapshot` で行います。来場者が購読するのは集計ドキュメント `board/public` と自分の整理券だけです。

### 5.1 データ設計（Firestore、`events/{eventId}` 配下）

| コレクション | 内容 | 読める人 |
| --- | --- | --- |
| `events/{id}` | 開催日時、状態（scheduled/open/closed/purged）、相談時間、復帰時間、採番、相談テーマ、全体の受付停止 | 自イベントの全員 |
| `secrets/codes` | 入場コード（7桁）、スタッフコード（8桁） | なし（Functions のみ） |
| `slots/{slotId}` | 公開プロフィール、種別、位置、停止、待ち上限（学生5／教員40）、占有者 | 開場中の来場者、スタッフ |
| `queues/{slotId}` | 待ち順の配列、スキップ一覧、対応中、直近10件の相談時間 | 担当スタッフ |
| `board/public` | 枠ごとの表示状態、待ち番号、目安時間の材料 | 開場中の来場者、スタッフ |
| `tickets/{id}` | 番号、状態、ブース、問診、各時刻、TTL | 本人、担当スタッフ |
| `visitors` / `staff` | 入場記録、有効整理券／役割、ブース、生存確認 | 本人、スタッフ |
| `auditLog` / `stats/{date}` | 操作履歴／個人性のない集計（恒久保持は stats のみ） | 管理者 |

整理券の状態は `waiting → calling → in_progress → completed` を基本に、`skipped`（復帰で waiting の先頭へ）、`canceled`、`expired`（閉場・復帰期限切れ）を持ちます。

### 5.2 画面一覧

| 利用者 | 画面 | パス |
| --- | --- | --- |
| 来場者 | 入場ゲート | `/` |
| 来場者 | 相談種別の選択、相談員一覧（学生相談のみ）、詳細・発券モーダル | `/slots` |
| 来場者 | 整理券モニター | `/ticket` |
| スタッフ | ログイン、担当設定、キュー操作 | `/staff` |
| 管理者 | ログイン＋TOTP、ダッシュボード、イベント設定、コード、枠の管理、統計 | `/admin` |

## 7. 前提・リスク・未決事項

最大のリスクは、iOS で画面をロックすると呼出が届かないことです。システムだけでは解決できないため、口頭呼出を運用に組み込みます。

### 7.1 前提

- 本番は 2027年3月20日（土）、開発は1名体制（年末年始 12/26〜1/4 は作業しない）
- 大学の外部クラウド利用申請で GCP 東京リージョンが承認される
- 既存の請求先アカウントを使える（Blaze に必要。未決定だと本番環境を作れない）

### 7.2 リスクと対策

| リスク | 影響 | 対策 |
| --- | --- | --- |
| 画面ロック中に呼出が届かない（iOS） | 不在スキップが増える | 画面に常時明記、Wake Lock、呼出3分で口頭呼出、5分でスキップ、復帰10分 |
| 入場コードの写真が SNS で広まる | 会場外から発券される | 発券数の急増を警告、管理画面で即時再発行、ポスターは貼り替えシール |
| 仕様の未確認事項が想定と違う | 設計の手戻り | 開発初週に Emulator で検証（7.4） |
| 当日の障害 | 受付不能 | 紙の番号札100枚、切替判断は管理者 |
| 請求先・クラウド申請の遅れ | 本番環境の構築が遅れる | 開発は Emulator で先行し、申請は 11月中に提出 |
