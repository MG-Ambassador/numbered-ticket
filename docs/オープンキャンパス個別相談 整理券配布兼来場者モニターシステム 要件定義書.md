# オープンキャンパス個別相談 整理券配布兼来場者モニターシステム 要件定義書

- **策定日**: 2026年11月11日
- **ステータス**: 確定版 (Ver 1.0)

---

## 1. プロジェクト概要・基本方針

### 1.1 背景と目的
大学のオープンキャンパスで実施される「個別相談（学生による相談・教員による相談）」において、来場者の待機列および拘束時間を最適化し、キャンパスツアーや模擬授業など他プログラムへの回遊性を高めることを目的とする。また、事前の簡易アンケート（問診票）により相談の質と回転率を向上させる。

### 1.2 運用上の基本制約（ゼロデバイス方針）
- **専用機材の不使用**: 会場への大型モニター設置や、受付用の専用タブレット端末の配備は一切行わない。
- **BYOD（各自のスマートフォン完結）**: 来場者は自身のスマートフォン、スタッフ（学生・教員）も各自のスマートフォンブラウザのみで全ての確認・操作を完結させる。
- **インストール不要**: App Store / Google Play からの専用アプリインストールは求めず、QRコード読み取りからブラウザ上で即座に動作するWebアプリケーション（SPA / PWA）として提供する。
- **回線フリー**: 学内Wi-Fiへの接続強制による窓口混雑・サポート負荷を避けるため、来場者の通常のモバイルデータ通信（4G/5G）でそのまま利用できる構成とする。

## 2. マルチブース・待ち行列（キュー）設計

相談の性質が異なる「学生による個別相談」と「教員による個別相談」を同一システム上で統合管理する。

| 項目 | 1. 学生相談ブース（指名型） | 2. 教員相談ブース（プール型） |
| :--- | :--- | :--- |
| **受付単位** | 学生スタッフ個人のタイルから指名選択 | 相談員は選ばない。「教員相談」を選ぶとそのまま問診・発券へ進む |
| **プロフィール** | ニックネーム、学部学科、学年、自己紹介、得意テーマのタグ（例: `#総合型選抜` `#一人暮らし` `#サークル`）を表示 | 個別の教員情報は出さず、相談可能な分野（カリキュラム、入試基準、進路等）を案内 |
| **キュー構造** | **相談員ごとの独立キュー**（学生Aの列、学生Bの列が個別に存在） | **単一の共通キュー**（待機列は1本で管理） |
| **呼出と割振** | 各学生スタッフが自分のスマホで自身の待機列から順次呼出 | 手が空いた教員スタッフが共通キューの先頭を「取得（呼出）」し、自身の座席番号へ誘導 |
| **混雑制御** | 特定の学生に予約が集中した場合、上限組数（例: 4組）で自動的に「一時受付停止」へ切替 | 稼働中の教員ブース数に応じた全体の目安待ち時間を算出・表示 |

## 3. アクセス制御・不正発券防止仕様

追加機材（動的QR表示用タブレット等）を用いず、紙のポスターのみで「外部からのいたずら発券」や「SNS・LINE等でのURL横流し」を防止するため、**URLフラグメント（`#code=XXX`）と履歴即時消去を組み合わせたハイブリッド認証**を採用する。

### 3.1 認証フロー（通常入場：会場でのQRスキャン）
1. 会場内に掲示された紙ポスターのQRコード（例: `https://oc.univ.ac.jp/#code=738`）を来場者がカメラで読み取る。
2. ブラウザ起動時、クライアント側JavaScriptがURLフラグメント（`#code=738`）を読み取り、本日の有効コードと照合する。
3. 照合成功と同時に、ブラウザの `localStorage`（またはCookie）に当日有効な認証済みフラグを保存する。
4. 直後に `window.history.replaceState(null, '', window.location.pathname)` を実行し、ブラウザのアドレスバーから `#code=738` を即座に消去して `https://oc.univ.ac.jp/` に書き換える。
5. 来場者はパスコードを手入力することなく、シームレスに相談種別の選択画面（学生相談／教員相談）へ遷移する。

### 3.2 URL共有・横流し時のブロック（フォールバック画面）
- 来場者がブラウザの共有メニューから友人にURLを送信した場合、アドレスバーからは既に `#code=738` が消去されているため、共有先には `https://oc.univ.ac.jp/` のみが届く。
- フラグメントを持たない状態でアクセスした端末には、**「会場内の掲示板に記載されている本日の3桁コードを入力してください」**というパスコード入力画面を表示し、会場外の第三者によるアクセス・不正発券を遮断する。
- カメラアプリの仕様等でフラグメントが欠落した現地来場者も、ポスターに併記された3桁コードを手入力することで問題なく入場できる。

## 4. セキュリティおよび個人情報保護要件

操作性や視認性を著しく損なうギミック（画面全体の電子透かし重畳や、長押し中のみ表示するPeeking方式など）は採用せず、**「快適で自然なUI操作」を維持したままリスクを根絶するデータ非保持・運用ルール設計**とする。

### 4.1 スタッフ（在学生・教職員）のプライバシー保護
- **実名の完全非公開**: 本名はシステム上に登録せず、ニックネーム（例: 「ソウタ」「M.K.」）または相談員コードのみで表示する。
- **個人特定要素の排除**: 出身高校名、極小規模なサークル名、個人のSNSアカウントが検索・特定され得る固有情報の掲載を禁止し、「球技系サークル」「文化系部活」「地方出身」等の抽象化されたタグ表記に統一する。
- **顔写真の任意化・イラスト推奨**: スタッフ画像は公式イラストアバターや似顔絵アイコンの利用を基本とし、実写真を掲載する場合も高解像度データを避け、背景を単一化したサムネイル画像に限定する。
- **開催時間外の非公開化**: オープンキャンパス終了時刻をもって公開画面をクローズし、プロフィール情報が恒久的にWeb上に残存しない制御を行う。

### 4.2 来場者（高校生・保護者）の個人情報保護
- **PII（個人特定情報）の完全非取得**: 氏名、電話番号、メールアドレス、高校名などの個人情報は一切入力させない。発券番号（連番）と端末ローカルのセッションIDのみで個人を識別する。
- **問診票（アンケート）データの当日自動消去（TTL）**: 発券時に入力された相談内容や自由記述メモは、相談完了またはイベント終了後24時間以内にデータベースから物理削除する。次年度に向けた分析用データとしては、個人性を完全に排した統計値（学年比率・質問カテゴリ集計）のみを残す。

### 4.3 スタッフ管理画面の権限統制
- 来場者用URLとスタッフ用URL（`/staff`）を分離し、スタッフ画面へは当日スタッフ専用のパスコード認証を必須とする。
- 通信は常時TLS（HTTPS）により暗号化する。

## 5. 機能要件詳細

### 5.1 来場者向け画面
1. **入場ゲート画面（自動認証 / コード入力）**
   - QRコード経由の自動認証処理、および未認証時の3桁パスコード入力フォーム。
2. **相談種別の選択画面**
   - 「学生相談」と「教員相談」の2択。それぞれに「現在の待ち組数」「目安待ち時間」「受付ステータス（すぐ案内可 / 受付中 / 一時停止中）」をリアルタイム表示。
   - 学生相談 → 3. 相談員一覧へ進む。
   - 教員相談 → 相談員の選択を行わず、4. 問診・発券へ直接進む（共通キューに並ぶ）。
3. **相談員一覧画面（学生相談のみ・タイル表示）**
   - 学生スタッフごとのタイルに「現在の待ち組数」「目安待ち時間」「受付ステータス」をリアルタイム表示。
   - タグによる絞り込み機能（例: `#総合型選抜` `#留学` `#理系`）。
4. **問診・発券（学生相談はプロフィール詳細つきのモーダル）**
   - 学生相談の場合のみ、選択した学生の詳細プロフィールを表示。
   - 任意回答の事前問診フォーム（学年選択、聞きたいテーマの複数選択チェックボックス、自由記述欄）。
   - 重複発券防止制御（1端末につき同時に有効な整理券は1枚のみに制限）。
5. **整理券・リアルタイム待機モニター画面**
   - 発券番号（例: No. 104）、予約先（例: 学生：ソウタ / 教員窓口）の表示。
   - 「あなたの前にあと〇組」「およそ〇分待ち」のリアルタイムカウントダウン。
   - 呼出ステータス変化時の画面強調バナー表示（「【お呼び出し中】ブースB-2へお越しください」）およびバイブレーション通知。
   - 来場者自身による「予約キャンセル」ボタン。

### 5.2 スタッフ向け画面（スマートフォン専用ダッシュボード）
1. **担当枠・ブース設定画面**
   - 学生スタッフ：自分の担当プロフィール枠を選択。
   - 教員スタッフ：「教員相談モード」を選択し、現在着席しているブース番号（例: 「B-2」）を設定。
2. **待機キュー・問診票確認画面**
   - 待機中の整理券リスト表示（番号、学年、質問カテゴリタグ）。
   - タップで個別の自由記述メモ（問診票カルテ）を事前閲覧し、相談開始前にパンフレット等を準備可能にする。
3. **ステータス操作パネル（ワンタップ制御）**
   - **「呼び出す」**: 対象チケットを `calling` に変更し、来場者画面に通知（教員モードでは排他ロックにより他教員との重複呼出を防止）。
   - **「相談開始」**: ステータスを `in_progress` に変更し、経過時間タイマーを開始（15分経過時に長期化注意インジケーターを表示）。
   - **「完了」**: ステータスを `completed` に変更し、次の待機者を繰上げ。
   - **「不在スキップ」**: 呼び出しても現れない場合、`skipped`（保留/不在）へ変更して次の組を案内。
4. **受付一時停止トグル（学生スタッフ用）**
   - 休憩やシフト交代に入る際、新規の発券受付を一時ストップする切り替えスイッチ。

## 6. 技術スタック・データベース設計

### 6.1 推奨技術スタック
- **フロントエンド**: Next.js (App Router) または React (Vite) + TypeScript + Tailwind CSS
- **バックエンド / DB**: Supabase (PostgreSQL + Supabase Realtime) または Firebase
- **リアルタイム同期**: WebSocketによるDB変更イベントの購読（ポーリング不要の即時画面更新）
- **ホスティング**: Vercel または Cloudflare Pages

### 6.2 データベーススキーマ（主要テーブル定義）

#### 1. `staff_slots`（相談窓口・スタッフマスタ）

| カラム名 | データ型 | 制約 | 説明 |
| :--- | :--- | :--- | :--- |
| `id` | UUID | PK | スロット一意識別子 |
| `name` | VARCHAR(50) | NOT NULL | 表示名（例: "ソウタ", "教員による個別相談"） |
| `slot_type` | VARCHAR(20) | NOT NULL | `student`（指名型）または `faculty`（プール型） |
| `faculty_name` | VARCHAR(50) | NOT NULL | 所属学部・学科名 |
| `grade_label` | VARCHAR(20) | NULL | 学生の学年表記（例: "3年"） |
| `tags` | TEXT[] | DEFAULT '{}' | プロフィールタグ配列 |
| `bio` | TEXT | NULL | 自己紹介・相談メッセージ |
| `avatar_url` | TEXT | NULL | アバター・イラスト画像URL |
| `is_active` | BOOLEAN | DEFAULT true | 新規発券の受付可否フラグ（休憩切替用） |
| `max_wait_limit` | INT | DEFAULT 4 | 最大待ち組数上限（超過時は自動受付停止） |

#### 2. `tickets`（発券チケット・問診票データ）

| カラム名 | データ型 | 制約 | 説明 |
| :--- | :--- | :--- | :--- |
| `id` | UUID | PK | チケット一意識別子 |
| `ticket_number` | INT | NOT NULL | 表示用整理券番号（101, 102...） |
| `slot_id` | UUID | FK | 予約対象の `staff_slots.id` |
| `assigned_booth` | VARCHAR(20) | NULL | 呼出先ブース番号（教員プール時の誘導先: "B-2"等） |
| `status` | VARCHAR(20) | NOT NULL | `waiting` / `calling` / `in_progress` / `completed` / `skipped` / `canceled` |
| `visitor_grade` | VARCHAR(20) | NULL | 来場者の学年（高3、高2、保護者など） |
| `categories` | TEXT[] | DEFAULT '{}' | 相談したいトピック配列 |
| `note` | TEXT | NULL | 自由記述メモ（イベント終了後24h以内に自動削除） |
| `created_at` | TIMESTAMPTZ | DEFAULT now() | 発券日時 |
| `called_at` | TIMESTAMPTZ | NULL | 呼出日時 |
| `started_at` | TIMESTAMPTZ | NULL | 相談開始日時 |
| `completed_at` | TIMESTAMPTZ | NULL | 相談終了日時 |
